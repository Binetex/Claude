# Floremart Constitution

## Core Principles

### I. Молчание безопаснее лишнего сообщения

Любое сообщение клиенту (SMS, письмо, автоответ) уходит ТОЛЬКО на английском и только тогда,
когда система уверена. Сомнение, сбой модели, нехватка данных — это черновик человеку или
тишина, а не угаданный ответ. Обещание, которое магазин не может выполнить (время, которого не
успеть, услуга, которой нет), клиенту не уходит никогда: такие ответы режутся проверкой в коде,
а не только инструкцией модели.

### II. Решает код, модель только формулирует

Всё, от чего зависит обещание клиенту (можно ли утро, до какого часа успеваем, нужен ли вопрос
клиенту), решает детерминированный код по данным. Модель получает готовое решение и пишет его
словами. Решение, живущее только в тексте промпта, — ошибка проектирования: его нельзя
проверить тестом и оно расходится с остальной системой.

### III. Одна правда — одно место

У каждого факта один источник и один модуль, который его считает: окно доставки — строгие
«с — до» (`lib/deliveryWindow.ts`), загрузка флориста — `modules/capacity`, доставка во времени —
оценка по фактическим доставкам. Второй способ посчитать то же самое не заводится; экран и
ассистент читают один и тот же расчёт. Выводимое (долг, загрузка, опоздание) выводится, а не
хранится копией.

### IV. Простота прежде всего

Не усложнять то, что делается проще с тем же результатом. Новые таблицы, сервисы, кэши и флаги —
только когда без них нельзя. Свободный текст там, где нужно значение, — источник регулярок и
ошибок: данные вводятся строго (выбор, а не поле ввода).

### V. Проверено до выкатки

Каждое изменение поведения закрыто тестом на реальных примерах из прода. Перед деплоем — полный
прогон тестов и проверка в браузере на тестовой базе для всего, что видно на экране. Миграции
только ДОБАВЛЯЮТ: старый код несколько минут работает с новой схемой. Удаление колонок —
отдельным деплоем.

### VI. Решения владельца записаны

Бизнес-правило, полученное от владельца (порог, время, «позже всегда выгоднее»), записывается в
CLAUDE.md с датой и причиной, в коде — константой с комментарием, откуда она. Правило не
«чинится» молча: изменение правила — только по слову владельца.

## Время, даты и данные

- Всё время, которое видит человек или модель, — по часам магазина (Лос-Анджелес), `lib/tz.ts`.
- `Order.deliveryDate` — UTC-полночь местного дня: через таймзону не прогоняется.
- Окно доставки — `Order.windowFrom` / `windowTo`, минуты от полуночи; текст окна пишет система.
- Внешние записи (Woo, Burq, SMS) — только через outbox с идемпотентностью; повтор не должен
  давать второго действия.

## Рабочий процесс

- Прод — чистый git-чекаут `main`; деплой только `./deploy.sh` (с автооткатом).
- Один смысловой блок — один коммит; секреты не коммитятся.
- Разовые скрипты по боевой базе — с сухим прогоном по умолчанию и флагом записи.
- Проверки соразмерны риску: один внимательный проход и тесты, без раздутых проверочных вееров.

## Governance

Конституция описывает, КАК принимаются технические решения; текущее устройство системы описано
в CLAUDE.md. Противоречие между ними решается в пользу конституции до явного решения владельца.
Изменение принципа — по слову владельца, с записью версии: MAJOR — принцип убран или переопределён,
MINOR — добавлен, PATCH — уточнение формулировок. Каждая спецификация (`specs/`) проходит проверку
на соответствие принципам в разделе Constitution Check своего плана.
